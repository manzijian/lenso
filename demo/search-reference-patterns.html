对比

这五类界面的共同规律

维度他们怎么做含义
图片尺寸列表里都是 20–40px 的小缩略图；要看清就切换成预览不要把“大图卡片”塞进搜索列表
每条的信息标题（或文字片段）+ 一个来源 + 一个时间不超过三段，绝不出现字数、路径、类型标签三件套
筛选要么竖向侧栏，要么干脆没有（分组标题代替）顶部一排胶囊是最占地方、收益最低的做法
预览Raycast 按需唤出；Eagle 固定右栏搜索场景更适合“固定右栏/按需”，不适合双击弹窗
焦点选中行整行变色或加描边键盘上下移动必须始终有一条高亮
元信息弱化到 9–10.5px、灰阶时间/来源是辅助，不该和标题抢注意力

落到 LENSO 的建议

骨架用 Raycast，图片交互借 Eagle，状态条借 CleanShot。具体是：顶部保留一条大搜索框（像现在这样，这个是优点）；下面不再用筛选胶囊，改成 左侧 120px 竖栏（全部 / 截图 / 文字 / 收藏，带数量）；中间是 32px 行高的紧凑列表，每行 = 24px 缩略图或类型图标 + 标题一行 + 来源应用图标 + 时间；右侧 260px 固定预览栏，选中即显示大图 / 全文和「复制 / 打开 / 删除」。

这样一屏能看到 12–15 条，图片在右边永远完整清晰，键盘 ↑↓ 直接切换预览，回车复制——和纯看图库的体验区分开。如果你更想要“最近几条、滑动挑选”的轻量感，那就走 Paste 的横向货架，但那会牺牲搜索密度。
